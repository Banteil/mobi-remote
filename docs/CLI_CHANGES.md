# 마비노기 모바일 AI 커넥터(CLI) 변경 기록

리모콘이 검증한 기준선(`mobi-remote/compat.json`, 2026-09-25, `0.1.0+0487c37…`)과 비교한 내용.
명령 목록·본문 형식(BodyExample)·비용은 그대로라 리모콘의 호환성 검사(명령|본문 지문, semver)로는 **안 잡힌다**.
설명(Note)과 출력 형식(OutputExample)만 바뀌었다 → 이식할 호환성 검사는 Note/OutputExample 도 지문에 넣는다.

## 2026-10-15 판 (`0.1.0+5898078…`, 파일 날짜 10-15) — 2026-10-21 확인

| 명령 | 바뀐 점 | 영향 |
|---|---|---|
| `get_music_scores` | 게임이 준 악보(NPC 상점·보상)만 나온다. **직접 만들거나 복사한 악보는 목록에서 빠진다** | 리모콘 캐시 164곡 → 지금 3곡(같은 캐릭터인지는 미확인). 재생목록은 보유 곡만 추려 연주하므로 커스텀 곡은 조용히 빠진다 |
| `play_music_score` | 커스텀 악보 제목이면 `user_composed_not_allowed` 로 거부 | 재생목록 루프는 거부 시 다음 곡으로 넘어간다 (멈추지 않음). 한국어 설명 필요 |
| `write_chat` | **매번 게임 안에 확인 창**이 뜨고, 사용자가 '보내기'를 눌러야 전송된다. 그동안 호출이 몇 분까지 멈춘다. 새 오류: `inappropriate_text`(서버 필터), `user_declined`(취소 — 같은 메시지 재전송 금지), `confirm_timeout`, `blocked`, `not_enough_currency` | 표정·행동도 write_chat 이므로 전부 확인 창. 화면에 "게임에서 확인을 누르세요" 안내와 긴 대기, 취소 처리 필요 |
| `execute_altering` | 새 오류 `queue_full` (시작 전 거부와 시작 후 둘 다) | 시설이 꽉 찼을 때 날개 5가 새던 문제를 게임이 직접 알려 준다 → 사전 차단과 함께 쓴다 |
| `get_alterable_items` | `Reason` 에 `queue_full` 추가 | **시설이 꽉 찼는지 조회만으로(무료) 알 수 있다** → 칸 추정 로직의 근거로 쓸 수 있음 |
| `execute_gathering` | 소모품(빈 병 등)이 바닥나면 목표 전에 `required_consumable_missing` 으로 멈춤(전에는 목표를 미리 낮췄다). 새 오류 `interrupted_by_attack` | 채집 목표 루프: 두 오류를 '진전 없음'과 구분해 안내 |

비용(채집·제작·가공 1회 날개 5), 명령 28개, 본문 형식은 변화 없음.

## 기존 리모콘(2.1.1)에서 지금 생기는 문제
- 연주: 커스텀 곡이 목록에서 사라짐 (오류 없이). 재생목록에 남은 커스텀 곡은 건너뜀.
- 소셜: 채팅·표정·행동이 게임 확인을 기다리며 멈춘 것처럼 보임 (시간 제한 없음).
- 새 오류 코드들은 한국어 설명이 없어 코드 그대로 표시됨.
